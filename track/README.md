# 无人机俯拍交通视频 —— 分割 + 跟踪 + 平滑渲染流水线

本包是 `E:\AAA-reseach` 中实际在跑的那套处理链路的完整快照（代码 + 配置 + 文档），
不含模型权重、视频与数据集。

- 任务：对无人机俯拍的道路视频做**实例分割** → **多目标跟踪（稳定编号）** → **时序滤波平滑** → **渲染成片**
- 模型：`yolo26x-seg` 微调权重 `best.pt`，3 类 `vehicle / rider / pedestrian`
- 跟踪器：Ultralytics 官方 **FastTracker**（ByteTrack 的遮挡感知变体），另附自研 7D 形状感知跟踪器（默认不启用）
- 输出：带掩膜套色、`编号 置信度` 标签的 mp4（可选 json 轨迹）

---

## 0. 快速开始

```bash
cd <项目根>

# 依赖：ultralytics 8.4.154（yolo26 分支）
python -u tools/track_segment.py \
  --source "<输入视频>.mp4" \
  --out    "<输出目录>/<名字>.mp4" \
  --out-dir "<输出目录>" \
  --model  "<权重目录>/best.pt" \
  --tracker fasttrack.yaml \
  --imgsz 1536 --no-crop
```

> ⚠️ 三个**必须显式给**的参数，否则会用错默认值：
> 1. `--model`：默认值指向**旧权重** `runs/segment/round3_744`，不是当前在用的新模型
> 2. `--imgsz`：默认 1280，但当前模型训练于 **1536** —— **推理尺度必须与训练一致**
> 3. `--out-dir`：只在 `--out` 为空时用于推导成片路径；**pass1 缓存与 json 跟随 `--out`**
>    （`<out>_pass1.pkl` / `<out>_tracks.json`），不是跟随 `--out-dir`

`--conf` / `--conf-init` 的默认值（0.3 / 0.75）是这个项目当前的选定值，一般不用再传。

## 3. 处理链路（按执行顺序）

整条链路分两个 pass：**pass1 逐帧检测+跟踪并缓存**，**pass2 平滑+渲染+编码**。
中间结果落盘为 `.pkl`，因此调参重跑只要缓存签名不变就**跳过推理**（约省 80% 时间）。

### 3.1 前置：读取与设备

- OpenCV 逐帧读，`--limit N` 可只跑前 N 帧（调试用）
- 推理设备由 `--device` 显式传入（默认 `0`），启动时打印实际设备与显卡名
- **全片分散采样 30~40 帧**，统计每一行的"有内容帧占比"，多数投票得出画面有效行范围
  `[eff_top, eff_bot]`，用于自动识别上下黑边（不受片头黑帧干扰）

### 3.2 pass1：检测 + 跟踪 + 采集

对每一帧：

1. **推理+跟踪**：`model.track(frame, persist=True, imgsz, conf, retina_masks=True, device, quantize)`
   - `retina_masks=True`：掩膜在原图分辨率上还原，避免低分辨率掩膜放大后锯齿
   - 跟踪器读 `--tracker` 指定的 yaml（默认 `fasttrack.yaml`）

2. **重复实例去重（身份感知）** —— 同一帧内两两比较，重叠比超过阈值才判重复：
   - 同类别用 `dedup_ratio 0.5`；`rider↔pedestrian` 用 `dedup_cross 0.8`；涉及其他类跳过
   - 三条裁决规则：
     - 两方**都已是已建轨迹** → 只有重叠 `> dedup_dup 0.9` 才去重（近乎完全重合），
       否则视为两个不同对象 —— 这条是"保住已建轨迹连续性"的关键
     - 一方已建、一方未建 → **删未建的那个**（不看置信度高低）
     - 其余 → 按置信度删低分
   - 历史背景：原实现只按"重叠+置信度"删，在密集人流里会互删相邻目标，
     甚至删掉某条轨迹正在续上的那一帧，导致对象整段消失

3. **两级置信度门限**（本项目定制，patched 在 `new_idx` 处）
   - `--conf 0.3`：**跟踪门限**，检测下限。已建轨迹续帧用它 → 遮挡/模糊时仍能续上
   - `--conf-init 0.75`：**首现门限**，只有 `conf >= 0.75` 才允许**建立新轨迹**
   - 已建轨迹的续帧**不受** `conf-init` 限制 → 不会打断已有身份
   - 作用：挡掉低分误检凭空建新号（实测 9.mp4：单 0.6 → 82 条，加首现 0.8 → 79 条）

4. **分配编号**
   - 每类**独立**从 1 开始；编号**永久占用，作废不复用**
   - 同帧内多个新对象按 `--order diag`（右上→左下对角）的空间顺序依次分配

5. **类别跳变容忍**（`--cls-tol 30`）
   - 跟踪器给了同一个 tid 就说明它认为是同一对象，类别只是标签。分类器对
     原地打转的 rider 常在 rider/pedestrian 间反复横跳
   - 连续跳变 ≤30 帧 → 保留几何、沿用轨迹自身类别；超过 30 帧才停收（疑为 ID 切换）

6. **掩膜几何采集**
   - `contour_to_poly`：`findContours` 取最大外轮廓 → `approxPolyDP(eps=0.004·周长)` 简化
   - `poly_resample`：按**弧长均匀重采样成固定 64 点**
     （定长才能做"第 i 个点跨帧对应"的时序平滑）
   - 只在 bbox 邻域内提轮廓，比全图 `findContours` 快一个量级

7. **缓存**：`{sig, tracks, stats, meta}` → `<out>_pass1.pkl`
   - `sig`（签名，`ver=5`）包含 source / model / imgsz / conf / **conf_init** / tracker /
     limit / cls_tol / 各 dedup 阈值 —— 任一变化即重算
   - ⚠️ **改了跟踪器或采集代码，签名不会变**，必须手动删 pkl 才会重算

### 3.3 pass1 之后：四个离线后处理

顺序固定，理由见括号：

#### (a) 轨迹缝合 `stitch_tracks`（先缝合，再过滤短轨迹）

同类别两条轨迹，若"前段尾部"与"后段头部"时间接近、位置吻合，就接成一条（保留前段编号）：

- `gap = 后段首帧 - 前段末帧`，要求 `1 <= gap <= --stitch-gap 40`
- 两端速度模长 ≤120 px/帧
- 用**前段末速度线性外推 gap 帧**，落在后段起点的**残差 ≤ --stitch-res 90 px**
- 端点在画面边界带（`--border-margin 60`）内**不缝** —— 可能正在离场/刚进场
- **不做速度方向夹角判断**（`--stitch-angle` 已弃用，仅为兼容旧调用保留）
- 迭代执行直到无可缝

> 为什么先缝后滤：一条 3 帧的碎片本身能桥接前后两段长轨迹，先删它等于把缺口从 3 帧
> 硬撑到几十帧，反而更难缝。

#### (b) 掩膜粘连修正 `fix_merged_masks`

**问题**：几个挨得近的目标，掩膜在某一帧突然糊成一个大块。

**判定**（同时满足）：
- 本帧有 ≥2 条别的轨迹**缺席**，且它们在 `--merge-look 3` 帧内刚消失
- 这些"刚消失"的末框有 ≥`--merge-cover 0.5` 的比例落在这个大框内
  （或同帧共存但被本掩膜包住 ≥70% 像素，限同类别）
- 本掩膜面积明显大于被吞的那些（> 1.2×）

**处理方式取决于大掩膜落在谁身上**（这是实测踩出来的关键区别）：

| 落点 | 判据 | 处理 | 为什么 |
|---|---|---|---|
| 已有轨迹 | 面积 > `--merge-area-ratio 1.45` × 前 15 帧中位 | **只丢该帧** | 前后帧都在，插值能把它还原成原本的小形状 |
| 新出生轨迹 | 整条 ≤ `--merge-max-len 12` 帧 | **整条删掉** | 新轨迹没有历史可插值，只丢帧等于对象凭空消失 |
| 长轨迹且未骤增 | 以上都不满足 | **不动** | 可能真是个大目标；宁可漏修，不误删 |

删掉/丢帧之后，被吞的那几个小掩膜由 (d) 的缺帧填补逻辑还原。

#### (c) 重复掩膜修正 `fix_overlap_conflicts`

**问题**：同一物体被检出两个掩膜（典型是同时判成 rider 和 pedestrian）。

**判定 —— 必须三条同时满足**：
1. 重叠比（`交集 / 较小掩膜面积`）≥ `--overlap-jump 0.80`
2. 质心距 / `sqrt(较小掩膜面积)` ≤ `--overlap-center 0.35`（几乎在同一位置）
3. 相对**这一对自身的历史中位**是突跳（`r - median ≥ --overlap-base 0.25`）

> ⚠️ **为什么不能只看重叠**：实测密集人流里两个**真实相邻**的行人，掩膜重叠可达 56%~70%，
> 质心只差 20~30 px（≈0.5 倍掩膜尺度）。按 0.55 的门限去删会把真人整帧删掉。
> 抬到 0.80 + 质心判据后，14.mp4 上命中 0 处 —— 这个视频没有真重复，只有真邻接。

**丢谁**：① 一方 conf < `--overlap-drop-conf 0.6` 而另一方不低 → 丢低分那个；
② 两边都低 → 丢 conf 更低的；③ 都不低 → 丢掩膜面积更小的那个。

#### (d) 短轨迹过滤

`--min-track-frames 5`，少于 5 帧的多为误检。放在缝合与伪影修正**之后**。

### 3.4 pass2：时序滤波 + 渲染

#### (a) 平滑 `smooth_tracks`

对每条轨迹，在 `[首帧, 末帧]` 的完整时间轴上：

1. **线性插值补短缺口**：`np.interp` 把 `cx, cy, w, h, conf` 全部插满
2. **分段**：只在"连续出现段"上平滑；短于 `--max-gap 45` 的缺口并回同一段，
   更长的断开（避免跨长缺失插出假目标）
3. **Savitzky-Golay 滤波**（自实现，不依赖 scipy）：
   - 框参数 `--smooth-win 15` / order 2
   - 掩膜轮廓 `--poly-win 11`
4. **掩膜轮廓专有处理**（顺序不能变）：
   - `_box_norm_poly`：轮廓转**框归一化坐标**（框中心为原点、宽高为单位）
   - **面积异常帧剔除**：`--poly-outlier 2.2`，面积相对 15 帧滚动中位偏离超 2.2 倍
     视为被遮挡/闪断的异常帧，先剔掉再插值
   - `_align_stack`：**循环位移对齐**（链式对齐 + 中位形状模板迭代 2 轮），
     保证"第 i 个点"帧间对应同一物理位置 —— 否则直接平滑会把不对应的点平均到一起，
     表现为多边形塌缩或鼓出框外
   - `_limit_shape`：**形状变化限速** `--shape-max 0.06`（框归一化单位），
     正向、反向各扫一遍再取平均（防单向拖尾）
   - `_clamp_q`：**收边**，把顶点沿"质心→顶点"射线收进 `[-0.5-tol, 0.5+tol]²`
     （`--clamp-tol 0.03`）；若收边后面积掉到 40% 以下说明质心已在框外，放弃收边
   - 按平滑后的框**反投影**回原图坐标
5. **缺帧填补**（`--poly-fill-gap 20` + `--fill-max-body 2.5`）
   - 同一编号在**中间**有几帧没识别到、但前后都在**相近位置**时，用插值把框和轮廓都补出来
   - 三个前提：①缺口在中间（前后都有真实观测，首尾不补）②缺口 ≤20 帧
     ③缺口两端中心距 ≤2.5 × `sqrt(w×h)`（防 ID 跳变时插出"穿越残影"）
   - ⚠️ 实现细节：`if not has[i]: continue` 在代码里出现**两处**
     （生成 poly_map 处 + 逐帧装配处），**两处都要放行**，否则补齐白做、
     成片里仍是"对象凭空消失"

#### (b) 渲染 `render_frame`

| 项 | 约定 |
|---|---|
| 矩形检测框 | **不画**（`--draw-box` 默认 False；`--no-box` 也显式 `default=False`） |
| 掩膜 | 轮廓线 `--line-width 3` + 半透明填充 `--mask-alpha 0.35` |
| 类别区分 | **只靠颜色**（BGR）：vehicle `(121,78,31)` 深蓝 / rider `(0,0,192)` 深红 / pedestrian `(143,157,42)` 青绿 |
| 标签文字 | **`{编号} {置信度:.2f}`**，如 `25 0.93` —— **不含类别名** |
| 标签位置 | **固定锚定在对象正上方、水平居中**：`x=(A+C)/2-tw/2`，`y=B-5`，仅做画布边界钳制 |
| 字号 | `--font-scale 0.45` |
| 标签底色 | `--label-bg` 默认开（类别色底衬 + 白字）；关掉则类别色描边 + 白字 |
| 叠加顺序 | 从下往上画（下方对象先占位） |

> 早期的"三档纵向位置 × 左右两种对齐 + 防重叠择位"逻辑**已删除** ——
> 那正是标签在对象周围乱跳的根源。

#### (c) 编码

原始帧 → 渲染 → 通过 stdin 管道直接喂给 `ffmpeg`（libx264，`--crf 20`），
不落中间帧文件。`--crop/--no-crop` 决定是否裁掉上下黑边（`--crop-pad 22`）。

#### (d) 输出

- `<out>.mp4`
- `<out>_tracks.json`：每类轨迹清单（编号、首末帧、帧数、平均置信度）+ 元信息
- `<out>_pass1.pkl`：pass1 缓存

## 4. 参数总表（默认值）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--source` | 必填 | 输入视频 |
| `--model` | 旧权重路径 ⚠️ | **必须显式指定当前权重** |
| `--imgsz` | `1280` ⚠️ | **必须与训练尺度一致**（当前模型 1536） |
| `--conf` | `0.3` | 跟踪门限（续帧） |
| `--conf-init` | `0.75` | 首现门限（建新轨迹） |
| `--tracker` | `fasttrack.yaml` | 跟踪器配置 |
| `--limit` | `0` | 只跑前 N 帧，0=全部 |
| `--out` | `None` | 成片路径（默认由 out-dir + 源名推导） |
| `--out-dir` | `videos/output/track` | 仅在 `--out` 为空时用于推导成片路径 |
| `--order` | `diag` | 编号空间顺序：diag=右上→左下对角，row=逐行从右到左 |
| `--dedup-ratio` | `0.5` | 同类别重复判定的重叠比 |
| `--dedup-cross` | `0.8` | rider↔pedestrian 跨类重复判定的重叠比 |
| `--dedup-dup` | `0.9` | 两条已建轨迹判为重复所需的重叠比 |
| `--smooth-win` | `15` | 框参数 SG 窗口 |
| `--poly-win` | `11` | 轮廓 SG 窗口 |
| `--poly-outlier` | `2.2` | 面积异常帧剔除倍数 |
| `--shape-max` | `0.06` | 轮廓形状变化限速 |
| `--clamp-tol` | `0.03` | 掩膜允许超出框的比例 |
| `--max-gap` | `45` | 平滑时段内允许跨越的最大缺口 |
| `--poly-fill-gap` | `20` | 缺帧填补的最大缺口帧数（0=关闭） |
| `--fill-max-body` | `2.5` | 缺帧填补的位置合理性（×目标尺度） |
| `--min-track-frames` | `5` | 短轨迹过滤 |
| `--stitch` / `--no-stitch` | 开 | 轨迹缝合 |
| `--stitch-gap` | `40` | 缝合允许的最大间隔帧数 |
| `--stitch-res` | `90.0` | 缝合外推残差门限（px） |
| `--stitch-angle` | `60.0` | **已弃用**（方向判断已移除） |
| `--cls-tol` | `30` | 类别跳变容忍帧数 |
| `--fix-merge` / `--no-fix-merge` | 开 | 粘连大掩膜修正 |
| `--merge-area-ratio` | `1.45` | 面积骤增判据（×前 15 帧中位） |
| `--merge-cover` | `0.5` | 消失近邻末框落在大框内的比例 |
| `--merge-look` | `3` | 近邻"刚消失"的帧数窗口 |
| `--merge-max-len` | `12` | 短粘连轨迹的整条删除上限 |
| `--fix-overlap` / `--no-fix-overlap` | 开 | 重复掩膜修正 |
| `--overlap-jump` | `0.80` | 重复判定：重叠比 |
| `--overlap-center` | `0.35` | 重复判定：质心距/√面积 |

## 5. 关键设计决策与踩坑记录

这些不是理论推导，都是实测踩出来的，改动前建议先读。

### 5.1 为什么默认跟踪器是 `fasttrack.yaml`

曾试过自研的 7D 形状感知跟踪器（`shape.yaml`，见 `docs/7D形状感知跟踪器_实现与评测.md`）。
在 9.mp4 上它只与 fasttrack 打平（80 轨迹 / 0 断裂 / 0 缝合），**最长缺失反而更差**
（59 vs 18 帧）；在 12/14 上缝合段数明显更多（12: 13 vs 2 段）。而且形状项对
**vehicle** 干扰大（车的掩膜面积变化被当成身份变化）。

> 结论：不做多跟踪器融合，也不要默认启用 7D。现成缝合 + 缺帧填补已经覆盖了它想解决的问题。

### 5.2 `argparse` 的隐式默认值会坑你

```python
# 错误写法：store_false 在没给 default 时会隐式把 default 设成 True
ap.add_argument("--no-box", dest="draw_box", action="store_false")
ap.add_argument("--draw-box", dest="draw_box", action="store_true")
# → draw_box 默认是 True，矩形框一直在画，怎么调顺序都没用
```
**两个互斥 flag 共用同一 `dest` 时，必须都写 `default=`。**

### 5.3 `--device` 曾经是摆设

定义了 `--device`，但 `model.track()` 调用里**从未传入**。Ultralytics 在 `device=None`
时会自动选 CUDA，所以"碰巧"是对的 —— 但日志里无从验证，环境一变就会静默退化到 CPU。
现已显式传入，且启动头部打印 `device : cuda:0 — <显卡名>`，pass1 汇总打印首帧张量设备。

### 5.4 跑长任务不要用 `| tail -N`

`tail` 必须读到 EOF 才输出，整个 pass1（几分钟）**一行进度都看不到**，
很容易被误判成"卡住"或"在跑 CPU"。用 `| tee <log>` 流式看。

### 5.5 交付前必须校验帧数

被中断的编码会留下 `moov atom not found` 的残片：文件大小看着像正常（56MB vs 73MB），
但帧数只有一半。`cv2.VideoCapture` 读出的 `CAP_PROP_FRAME_COUNT` 必须等于源视频帧数。

### 5.6 自研跟踪器的两个致命坑（若启用 `shape.yaml`）

1. **必须覆盖 `STrack.tlwh` / `xywh`**：基类假定 `mean[:4] = (cx, cy, w, h)`，
   而 7D 状态里 `mean[2:4]` 是**速度** —— 不覆盖则 bbox 退化成一条线，IoU 恒为 0/1，跟踪彻底失效
2. **`lost_stracks` 必须按 `max_frames_lost` 淘汰**：否则早期丢失的轨迹永远留在匹配池里，
   几百帧后被不相干目标重新匹配上（实测有条轨迹只有 30 个真帧，却横跨 0→712 帧）

### 5.7 外部论文的阈值不能照搬

7D 那篇论文的消融说"IoU 门限 0.3 优于 0.5"，但那是**纯掩膜 IoU** 代价。
本实现的门限卡在**融合代价**（IoU ⊕ 形状）上，同一个 0.3 等于一扇紧得多的门。
→ 只有代价函数的定义与量纲一致时，阈值才可直接借用。

### 5.8 掩膜多边形不是"贴合轮廓"的

因为经过 `approxPolyDP` 简化 + 64 点弧长重采样 + 时序平滑，最终多边形呈**带棱角的多边形**，
不贴合原始轮廓。这是为"可做时序平滑"而付的代价。若要更贴合：调小 `eps_ratio` 或提高
`CONTOUR_POINTS`，代价是平滑效果变弱、文件变大。

### 5.9 数据划分/训练侧注意事项

- 当前权重训练于 `imgsz=1536`，训练数据 `data2_cropped` **不在本机**（他人机器上训练，只拿回权重）
- 因此**推理 `imgsz` 必须 1536**，且"训练用裁剪数据、推理用全图"这一域差异仍待验证
  （在黑边窄的视频上影响小，如 9.mp4；黑边宽的源视频需先抽帧验证分布）

## 6. 自研 7D 形状感知跟踪器（`shape.yaml`）

文件：`ultralytics_patch/trackers/shape_tracker.py`

状态定义：`x = [x, y, ẋ, ẏ, a, r, θ]ᵀ` —— 质心 + 速度 + 掩膜面积 / 宽高比 / 朝向
（`θ = 0.5·atan2(2μ11, μ20−μ02)`，二阶图像矩）。质心恒速，**形状静态**。
观测矩阵 H 为 5×7（投影到 `x, y, a, r, θ`）。自带 `KalmanFilterXYAH` 把状态硬编码成
8 维 XYAH 改不动，所以另写了一个约 120 行的自洽滤波器。

**启用步骤**（默认不用，理由见 §5.1）：

1. 把 `shape_tracker.py` 放到 `ultralytics/trackers/` 下
2. 在 `ultralytics/trackers/track.py` 的 `TRACKER_MAP` 增加 `"shape": ShapeTracker`，
   并在 `trackers/__init__.py` 导出 `ShapeKalmanFilter7D / ShapeSTrack / ShapeTracker`
3. 把 `tools/trackers/shape.yaml` 复制到 `ultralytics/cfg/trackers/`
   （**必须放 cfg 目录**，否则 `--tracker shape.yaml` 解析不到）
4. `--tracker shape.yaml`，然后**务必删掉对应 pass1 缓存**再跑

调好的参数：`track_buffer 90`、`shape_weight 0.35`、`shape_iou_thresh 0.70`、
`shape_area_ratio_occ 0.55`、`shape_coast_max 15`、`fuse_score True`。

## 8. 已知局限

1. **掩膜不贴合轮廓**（§5.8）
2. **训练/推理域差异**未验证到黑边宽的源视频（§5.9）
3. **缺帧填补是插值**，不是重新检测：走动不匀速时位置会偏线性（有前后观测与距离判据约束）
4. **粘连块的"还原"依赖被吞目标的自身历史**：若被吞的那几个目标本身寿命极短（<5 帧），
   会被短轨迹过滤掉，那一小块区域就补不回来
5. **重复掩膜判据偏保守**（0.80 + 质心）：真重复能抓住，但两个几乎完全重合的真实目标
   （极端遮挡）会被误判一个
6. `--stitch-angle`、`docs/track_segment.md` 中的部分描述已过时，仅保留作历史参考
