## 2. 需求是怎么实现的

### 2.1 检测
- 模型 `best.pt`，`imgsz=1280`（与训练一致：原图 2560x1440 缩到 1280）
- **置信度阈值 0.65**，`quantize=16`（FP16，提速约 55%，精度差异可忽略）
- `retina_masks=True` 输出原图分辨率的掩膜，保证轮廓精细

### 2.2 编号规则（每个类别独立，从 1 开始）

| 规则 | 做法 |
|---|---|
| 每类独立编号 | `vehicle` / `rider` / `pedestrian` 各自从 1 开始 |
| 一个对象占一个编号 | 由跟踪器保证；轨迹被缝合后编号不变 |
| 编号永久占用 | `used_numbers` 记录已用编号，对象消失后该号作废，**绝不会**分配给后来的对象 |
| 视频之间互相独立 | 每个视频新建跟踪器与计数，互不影响 |
| 右上角 → 左下角递增 | 对角扫描：`key = (cy - cx, cy)`，右上 x 最大 y 最小 → key 最小 → 最先编号 |
| 同帧多个新对象 | 先按上述 key 排序，再依次分配 |

### 2.3 去重（避免同一像素出现多个目标）
两道防线：

1. **结构性**：一个 `track_id` 在同一帧只对应一个实例，同一编号不可能在一帧出现两次。
2. **去重规则**（`pass1_collect`）：
   - 同类别：重叠比 > `--dedup-ratio`（默认 0.5）→ 丢弃低置信度那个
   - `rider` vs `pedestrian`：重叠比 > `--dedup-cross`（默认 0.8）→ 丢弃低置信度那个
     （画面边缘被切断的对象常被同时判成这两类，框几乎完全重合）

不与 `vehicle` 做跨类去重——大框可能合法地包含小目标。

### 2.4 平滑（消除抖动、提高平滑度）

**离线两遍处理**（不追求实时，只追求质量）：

- **Pass 1**：逐帧推理 + 跟踪，把整条轨迹存下来
- **Pass 2**：对整条轨迹做时间域处理，再统一渲染

平滑内容：
1. **短间隙线性插值** — 最长 45 帧内的缺失补齐（避免闪烁）
2. **Savitzky–Golay 滤波** — 对质心 (cx,cy)、尺寸 (w,h)、置信度分别平滑，
   窗口 15 帧，2 阶多项式。自实现，不依赖 scipy
3. **分段处理** — 跨度过长的缺失不插值，避免凭空造出目标
4. **掩膜轮廓的时序处理** — 见下节，是本流程最容易出错的一环

### 2.4.1 掩膜轮廓的时序稳定（关键）

轮廓按弧长重采样成固定 64 点后，**每帧的第 i 个点并不对应同一个物理位置**
（起始点会沿轮廓漂移、形状会变形）。若直接对第 i 个点做时间平滑，等于把
不对应的点平均到一起 —— 表现为多边形**突然塌缩成很小的几何**、或
**鼓出检测框之外**。这不是模型输出不稳，而是平滑环节引入的。

处理顺序（`smooth_tracks` 内）：

| 步骤 | 做法 | 作用 |
|---|---|---|
| a. 异常帧剔除 | 面积偏离滚动中位 > `--poly-outlier`（2.2x）的帧标记为异常 | 去掉遮挡/闪断导致的孤立骤缩骤胀 |
| b. 循环位移对齐 | 先把轮廓按**框归一化**（框中心为原点、框宽高为单位），再按循环位移对齐到同一起点（链式对齐 + 中位形状模板迭代 2 次） | 保证"第 i 个点"帧间对应同一物理位置，这是平滑成立的前提 |
| c. 时间平滑 | 逐点在时间轴上插值后做 Savitzky–Golay（窗口 `--poly-win`=11） | 消除抖动 |
| d. 形状限速 | 相邻帧轮廓点平均位移 ≤ `--shape-max`（0.06，框归一化单位）；正向/反向各限幅一遍取平均 | **直接落实"连续几帧不要有太大形状变化"** |
| e. 收边 + 反投影 | 顶点沿"轮廓质心→顶点"射线收进框内（允许 `--clamp-tol`=0.03 的溢出），再乘回平滑后的框宽高、加上平滑后的框中心 | 掩膜不超出检测框；框与掩膜共享同一套平滑后的位置/尺度，不会脱节 |

**收边保护**：若收边会把轮廓面积压到 40% 以下（质心已在框外），放弃收边，
避免把有效轮廓压塌。

实测效果（8 个视频全部一致）：

| 指标 | 原始掩膜 | 旧版平滑 | 新版平滑 |
|---|---|---|---|
| 多边形超出框（中位） | 6.7~8.8% | 13.2~15.9% | **3.0%** |
| 超框 >15% 的轨迹 | 2~37 条 | 23~166 条 | **0 条** |
| 面积帧间跳变（中位） | 1.38~1.75x | 7.46~49.50x | **1.14~1.24x** |
| 形状突变（中位） | — | 0.199~0.257 | **0.047~0.060** |

回归验证脚本：`tools/verify_mask_fix.py`（原始/旧版/新版三方对照）、
`tools/mask_ab.py`（逐帧掩膜对照图）、`tools/diagnose_masks.py`（点序漂移诊断）。

### 2.5 轨迹缝合（消除编号跳变）

对象被遮挡或漏检时会断成两条轨迹，导致换号。`stitch_tracks` 迭代地把这种碎片接回去：

判定条件（全部满足）：
- 同一类别
- 前段结尾 → 后段开头，时间间隔 ≤ `--stitch-gap`（默认 40 帧）
- 用前段速度外推到后段起点，残差 ≤ 90 px
- 两段速度方向夹角 ≤ 60°
- **前段不是"正在走出画面"** —— 用「位置在边界带内 + 速度指向画面外」判断。
  走出画面意味着对象已离场，之后出现的是新对象，不缝合

缝合后**保留前段的编号**，后段编号作废。

### 2.6 渲染样式

| 元素 | 取值 |
|---|---|
| 掩膜 | 填充 + `addWeighted` 透明度 0.35 |
| 掩膜/框线 | 线宽 3 |
| 标签内容 | `类别 #编号 置信度` |
| 字号 | `font-scale=0.6`（用户要求"稍微小一点"） |
| 配色 | vehicle 深蓝 `#1F4E79`、rider 深红 `#C00000`、pedestrian 青绿 `#2A9D8F` |
| 标签避让 | 三档纵向位置 × 两种横向对齐，择优放置，避免标签互相遮挡 |
| 输出画面 | **裁掉上下黑边**，检测仍在完整画面上做 |

## 3. 为什么要裁剪黑边

每个视频的上下都有大片黑边，有效画面只占很小一部分：

| 视频 | 有效行 y ∈ | 有效高度 |
|---|---|---|
| 1.mp4 | [434, 1005] | 572 |
| 2.mp4 | [454, 984] | 531 |
| 5.mp4 | [466, 973] | 508 |
| 8.mp4 | [504, 935] | 432 |

原始 2560x1440 里**只有约 30~40% 是有效画面**。

处理方式：
- 检测、跟踪、掩膜全部在**完整原图**上做（与训练数据同分布，精度不受影响）
- **只在输出时裁剪**，上下各多留 22 px 余量

黑边范围自动检测：全片分散采样 40 帧，逐行统计"有内容"的帧占比，取 >50% 的行区间。
用多数投票而不是只看头几帧，避免视频开头的黑帧把整幅画面误判成黑边。

## 4. 质量审计（`<n>_audit.txt`）

逐条对应需求验收：

| 章节 | 检查内容 |
|---|---|
| **[A] 同帧像素重叠** | 同类别、跨类别分别统计掩膜重叠比——直接回答"同一像素是否出现多个目标" |
| **[B] 编号唯一性与连续性** | 每个 (类别, 编号) 只对应一条轨迹；列出作废编号 |
| **[C] 编号跳变** | 区分「走出画面属正常离场」与「画面内部真断裂」 |
| **[D] 平滑效果** | 一阶抖动、二阶急动的降低比例，以及平滑带来的位置偏离代价 |
| **[E] 轨迹覆盖** | 轨迹长度分布、缺失帧统计、同帧内编号是否重复 |
| **[F] 掩膜时序稳定性** | 多边形超出检测框的比例、面积帧间跳变、形状突变，并列出最不稳的轨迹 |

> ⚠ **[F] 的统计口径要注意**：必须把「连续帧（gap=1）」和「跨缺失帧（gap>1）」分开看。
> 连续帧才是肉眼看到的帧间变化，由 `--shape-max` 直接约束；
> 对象中间若干帧未渲染时，累加变化天然更大（实测跨缺失帧的形状突变可达 0.37，
> 而同一批数据连续帧的最大值正好卡在 0.060），混在一起统计会得出错误结论。
> 参考值（视频 1，249 条轨迹 / 192645 个连续帧对）：
> 连续帧形状突变最大 **0.060**、超 0.15 占 **0.0%**；连续帧面积跳变最大 **1.259**、超 1.5x 占 **0.0%**；
> 超出检测框 >15% 的轨迹 **0 条**。

审计会自动应用与主流程一致的短轨迹过滤（`--min-track-frames`，默认 5 帧），
否则 1~4 帧的误检会被误报成"轨迹断裂"。

单独重跑审计：

```bat
env\yolo26\python.exe tools\audit_tracks.py videos\output\track\2_track_pass1.pkl
```

**参考基线**（视频 2 前 800 帧）：
- 同类别最大重叠 0.022、跨类别 0.009 —— 均远低于 0.3 阈值
- 画面内部真断裂 0 处（缝合前 12 处全部消除）
- 二阶急动降低 85%、一阶抖动降低 32%，位置偏离代价仅 0.46 px
- 同帧内编号重复 0 次

## 5. 只改样式不重跑推理

Pass 1 的结果缓存在 `<n>_track_pass1.pkl`。参数签名（模型/imgsz/conf/tracker/帧数）不变时会自动命中缓存，
于是调整配色、字号、透明度、裁边等只需几秒：

> ⚠ **改 `--conf` 会让缓存失效**（它属于签名的一部分），必须重新推理。
> 而 `--poly-win` / `--shape-max` / `--clamp-tol` / `--poly-outlier` 只影响 Pass 2，
> 命中缓存即可几秒内重出片，调参很方便。

```bat
env\yolo26\python.exe tools\track_segment.py ^
  --source videos\2.mp4 ^
  --cache videos\output\track\2_track_pass1.pkl ^
  --out videos\output\track\2_preview.mp4 ^
  --font-scale 0.7 --mask-alpha 0.5
```

## 7. 跟踪器选型依据

用同一段视频（2.mp4 前 800 帧，检测结果完全相同，只有关联算法不同）对比，
指标是**轨迹条数**（越少说明同一对象越少被拆开）：

| 配置 | 耗时 | 无目标帧 | 每帧目标 | vehicle | rider | pedestrian |
|---|---|---|---|---|---|---|
| botsort buf30（默认） | 86s | 0.0% | 14.61 | 1 / 800 | 9 / 434 | 19 / 237 |
| botsort buf90 | 83s | 0.0% | 14.61 | 1 / 800 | 9 / 434 | 19 / 237 |
| botsort buf180 | 86s | 0.0% | 14.61 | 1 / 800 | 9 / 434 | 19 / 237 |
| botsort buf90 + ReID | 87s | 0.0% | 14.61 | 1 / 800 | 9 / 434 | 19 / 237 |
| **deepocsort buf90** | **70s** | 0.0% | 14.61 | 1 / 800 | 9 / 434 | **18 / 270** |

（单元格 = 轨迹条数 / 轨迹长度中位数）

结论：
- **deepocsort 胜出** —— 行人轨迹条数更少、中位长度更长（270 vs 237），且速度更快
- botsort 的 `track_buffer`（30/90/180）与 ReID **完全无影响** —— 说明本场景检测很稳、
  没有长遮挡；断裂主要发生在画面边缘对象出入时，靠离线缝合比调跟踪器更直接
- 相机基本静止（60 帧内背景位移 < 4 px），故 `gmc_method: none` 合理

重现该对比：

```bat
env\yolo26\python.exe tools\compare_trackers.py --source videos\2.mp4 --limit 800
```

## 8. 已知限制

| 情况 | 说明 |
|---|---|
| 画面边缘的目标 | 被切断时可能被误判类别（模型问题）；已用跨类去重缓解 |
| 长时间遮挡 | 靠缝合（最长 40 帧）恢复；更长的遮挡无法还原 |
| 编号顺序 | 只在对象**首次出现**时决定，之后固定不变——这是"编号永久占用"的必然结果 |
| 出现后又消失的编号 | 会留下空号（如 pedestrian 有 1~19 但只有 18 条轨迹），这是符合需求的设计 |
