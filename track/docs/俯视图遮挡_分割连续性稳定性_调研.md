# 俯视图遮挡下保持分割连续性与稳定性的方法调研

调研日期：2026-09-30
场景：无人机俯拍交通视频（2560×560/800/900，30fps），类别 vehicle / rider / pedestrian
核心问题：物体在上空遮挡（树冠、电线、桥、建筑、隧道）下，目标在图像上出现**间歇性空洞/掩膜闪断**，
      造成轨迹编号跳变、掩膜时序抖动、目标短暂丢失。

> 本报告的结论均已对照本机 `E:\AAA-reseach\yolo26\ultralytics`（v8.4.154）**实际代码验证过可用性**，
> 不是纸面建议。

---

## 一、先厘清：俯视图遮挡与地面视角遮挡的本质区别

| | 地面/车载视角 | **俯视/无人机视角（本项目）** |
|---|---|---|
| 遮挡来源 | 近处物体遮远处物体（斜向） | 遮挡物在**目标上方**（树冠、电线、桥、隧道、建筑） |
| 被遮挡表现 | 目标下半身被挡，仍可见上半部 | 目标被切成**若干可见碎片**，或整体瞬间消失 |
| 分离性 | 遮挡物与目标在同一深度层附近 | 遮挡物与目标深度差大，**语义上可分** |
| 时序特征 | 随视角变化缓慢 | **帧间二值跳变**（树冠缝隙扫过 → 忽隐忽现） |
| 主要失效模式 | ID 交换 | **掩膜闪断、编号跳变、掩膜面积脉冲** |

关键推论：俯视场景下**「检测不到」往往不是因为目标真的不可分，而是被高空遮挡物切断了连通域**。
因此应对手段的重心应从"更强的检测器"转向 **①训练时教会模型补全遮挡 ②跟踪层容忍短暂丢失 ③后处理层修复掩膜碎片**。

## 二、YOLO / Ultralytics 官方方案（v8.4.63+ 已本机可用，最重要）

### 2.1 换跟踪器 —— 官方明确列了「遮挡处理」这一列

Ultralytics 8.4.63 起内置 **6 个跟踪器**，官方文档的对比表专门有一列叫「遮挡处理」。
本机 `yolo26/ultralytics/trackers/track.py:21-26` 已全部注册，**无需升级**：

| 跟踪器 | 配置文件 | 遮挡处理机制 | 是否本机可用 |
|---|---|---|---|
| **BoT-SORT** | `botsort.yaml` | 跟踪缓存 + ReID 重关联 | ✅ |
| **ByteTrack** | `bytetrack.yaml` | 两阶段低置信度补救 | ✅ |
| **OC-SORT** | `ocsort.yaml` | ORU / OCM / OCR 从最后观测重新更新 | ✅ |
| **Deep OC-SORT** | `deepocsort.yaml` | OC-SORT + 可选自适应外观 EMA | ✅ |
| **FastTracker** | `fasttrack.yaml` | **Kalman 回滚 + 遮挡时扩大 bbox** | ✅ |
| **TrackTrack**（8.4.63+ 默认） | `tracktrack.yaml` | 迭代式多线索关联 + TAI | ✅ |

**官方选型指引（原文）**：
- 「手持设备、**无人机**或移动相机拍摄的视频？」→ **BoT-SORT**（增加相机运动补偿 + 可选 ReID）
- 「实时场景中**频繁发生部分重叠**，且没有 ReID 预算？」→ **FastTracker**（遮挡感知 ByteTrack 变体）
- 「频繁发生**遮挡**且重复 ID 是问题的拥挤场景」→ **TrackTrack 或 Deep OC-SORT**

> ⚠️ **对分割模型的特别提醒（官方原文）**：
> 「对于**分割**和姿态模型，TrackTrack 会**跳过宽松 NMS 检测恢复**，以确保掩膜和关键点与对应检测结果保持对齐。」
> → 意味着 TrackTrack 在分割任务上**放弃了它的一部分低分召回能力**。
> **本项目是 seg 任务**，这条直接削弱了 TrackTrack 的卖点，值得注意。

### 2.2 FastTracker 的遮挡专用参数（本机 `fasttrack.yaml` 原文）

这是**唯一以"遮挡"为设计中心**的跟踪器，参数直接对应"遮挡时怎么办"：

```yaml
reset_velocity_offset_occ: 5    # 遮挡开始时回溯 5 帧恢复 KF 速度
reset_pos_offset_occ: 3         # 遮挡开始时回溯 3 帧恢复 KF 位置
enlarge_bbox_occ: 1.1           # 遮挡时把预测 bbox 高度放大 1.1 倍（扩大搜索范围）
dampen_motion_occ: 0.5          # 遮挡时速度乘 0.5（减速，避免冲过头）
active_occ_to_lost_thresh: 10   # 连续遮挡超过 10 帧才标记 lost
occ_cover_thresh: 0.7           # 被其他轨迹覆盖面积占比 ≥0.7 判定为遮挡
occ_reappear_window: 40         # 最近被遮挡的丢失轨迹保持"可重新找到"的帧数
init_iou_suppress: 0.7          # 与活动轨迹 IoU≥0.7 时禁止初始化新轨迹
```

**官方针对遮挡的调参建议（原文）**：
- 频繁发生部分遮挡 → **降低 `occ_cover_thresh`**（如 `0.5-0.6`）—— 让遮挡判定更敏感
- 重叠区域附近出现重复 ID → **降低 `init_iou_suppress`**（如 `0.5`）
- 长时间遮挡 → **同时提高 `occ_reappear_window` 和 `track_buffer`**
- 快速移动的目标 → 提高 `dampen_motion_occ`（接近 `1.0`）

> **本项目已做的正确动作**：`tools/trackers/official_fasttrack.yaml` 已把 `track_buffer` 从 30 提到 **90**
> （注释写明依据：9.mp4 最长缺失 39 帧、缺失段 354 段，30 帧窗口够不着）。这个方向是对的。

### 2.3 通用遮挡参数（几乎所有跟踪器共有）

| 参数 | 默认 | 遮挡场景建议 | 原理 |
|---|---|---|---|
| `track_buffer` | 30 | **提高**（60~120） | 丢失轨迹保留帧数；官方原文「数值越大，对遮挡的容忍度越高」 |
| `match_thresh` | 0.8 | 提高（0.85~0.9） | 匹配更宽松，遮挡后更容易重新关联 |
| `track_low_thresh` | 0.1 | 略降 | 让低分框参与第二阶段补救 |
| `new_track_thresh` | 0.25 | 提高 | 减少遮挡造成的重复编号 |
| `fuse_score` | True | 保持 True | 融合置信度与 IoU，稳定弱检测 |
| `with_reid` | False | **遮挡严重时开 True** | 官方原文「enable appearance-based matching for better tracking **across occlusions**」 |
| `appearance_thresh` | 0.8 / 0.9 | 提高（0.85+ / 0.92-0.95） | 更严格的外观匹配，防 ID 交换 |
| `gmc_method` | sparseOptFlow / none | 无人机场景保持 sparseOptFlow | 补偿相机运动 |

**ReID 模型（新增能力）**：`model: auto` 会用 **YOLO 主干原生特征**，只增加极小开销；
也可指向 `yolo26n-reid.onnx`（首次运行自动下载，448px，2.8M 参数 / 2.0 GFLOPs）。
→ 对本项目：**可以先试 `with_reid: True` + `model: auto`**，几乎零成本买一层遮挡保险。

### 2.4 训练侧的遮挡增强（Ultralytics 官方训练参数）

官方 `default.yaml` 里与遮挡直接相关的训练增强（本机均存在）：

| 参数 | 默认 | 作用（官方原文） | 对分割是否支持 |
|---|---|---|---|
| `copy_paste` | 0.0 | 复制粘贴目标实例，**需要多边形标签** | ✅ 仅 segment/obb |
| `copy_paste_mode` | `flip` | `flip`=同图内复制；`mixup`=跨图复制 | ✅ |
| `cutmix` | 0.0 | **「创建真实遮挡场景的同时保持局部特征完整」** | ✅ |
| `mixup` | 0.0 | 全局混合像素，学"软边界"与语义连续性 | ✅ |
| `mosaic` | 1.0 | 已有，本项目在用 | ✅ |
| `hsv_*` / `erasing` | — | 颜色扰动 / 随机擦除（擦除仅分类） | — |

**官方关键实现约束（写死在代码里，改不了）**：
- `copy_paste`：只有当新目标与图中已有目标的 **IoA 全部 < 0.3** 时才粘贴（阈值硬编码不可调）
- `cutmix`：只有不覆盖任何已有 bbox 的区域才粘贴；保留 bbox 的最小面积阈值为
  **检测 0.1（10%）/ 带 segments 时 0.01（1%）**（阈值硬编码不可调）

**外部实践经验（YOLOv12 官方镜像的梯度配置，来自检索）**：
模型越大增强越强 —— N: mixup 0.0 / copy_paste 0.1；S: 0.05 / 0.15；**M/L: 0.15 / 0.4~0.5**；X: 0.2 / 0.6。
> 本项目用的是 **yolo26x-seg（最大档）**，按此规律可考虑 `copy_paste: 0.5~0.6` 量级。
> 另有实战经验：**别在训练初期就开 copy_paste**（前 10 epoch 关掉，之后渐开）；每张图最多粘贴 2 个物体；
> 与 mosaic 配合效果更好。

## 三、学术界的方法（针对"俯视 + 分割 + 遮挡"的专门工作）

### 3.1 ★ 形状感知卡尔曼滤波（Segment-based UAV Tracking via Shape-Aware Kalman Filter）

**这是与"分割掩膜 + 遮挡"最贴合的一篇**（Korea Science，2026），也是本报告最有价值的外部参考。

**核心思想：把卡尔曼状态从 4 维扩到 7 维，用"几何签名"锁身份。**

```
传统：x = [x, y, ẋ, ẏ]                       ← 仅质心+速度
本文：x = [x, y, ẋ, ẏ, a, r, θ]ᵀ              ← 增加 面积 a、宽高比 r、朝向 θ
```
- `a` = 掩膜前景像素总数；`r` = 掩膜 bbox 宽/高；`θ` = 由**二阶图像矩**推导的朝向
- 运动假设：**质心恒速，几何参数静态**（`F` 中几何项为单位阵）
- 关联：**掩膜级 IoU** + 贪心匹配
- 丢失容忍：**连续 10 帧未匹配才终止轨迹**

**为什么对遮挡有效（原文机理）**：
> 「UAV 交叉导致**部分遮挡**时，边界框方法因空间模糊无法维持身份，而本方法通过跟踪每个目标的
> **独特几何签名（unique geometric signature）**提升身份连续性。」

**关键实测结论（对本项目极有参考价值）**：
| 结论 | 数值 |
|---|---|
| ID 切换降低 | **最高 84~85%**（98 → 14.8，约 6 倍） |
| MOTA | 0.933（RGB）/ 0.931（IR），提升 3.7% |
| 效率 | IR >115 FPS；RGB/全流程 >40 FPS；1.14M 参数 / 1.77 GFLOPs |

> **★ 最重要的一条：IoU 阈值消融**
> | IoU 阈值 | IDSW | MOTA |
> |---|---|---|
> | **0.3** | **14.8（最低）** | **0.900（最高）** |
> | 0.4 | 18.1 | 0.896 |
> | 0.5 | 23.4 | 0.882 |
>
> 作者原文结论：「**过于严格的匹配条件会加剧身份碎片化**」，实际部署应采用 **0.3**。
> → 对本项目：`match_thresh` 若设得太严（缺省 0.8 的相似度门限），
> 恰恰会加剧遮挡后的编号碎片化。**这是与直觉相反但很重要的一条。**

**其局限（须知）**：该文**没有**掩膜分裂/部分缺失的专门修复算法，仅靠「几何预测延续 + 10 帧容忍 +
未匹配检测新建轨迹」；也**没有 ReID**，长期身份保持列为未来工作。且 7D 在遮挡有限的 Anti-UAV 上
与 4D 无差异（MOTA/IDSW 完全相同）—— 说明**几何签名的收益只在遮挡严重时才显现**。

### 3.2 其他相关方向（论文级）

| 方向 | 代表工作 | 要点 |
|---|---|---|
| UAV 视频实例分割 | **HT-VIS**（层次偏移补偿 HOC + 时序记忆更新 TMU） | ConvLSTM 建立帧间时序动态上下文，补偿柔性目标形变 |
| Transformer 分割 | **TF-YOLOv7** | Swin Transformer 分层特征 + Bottleneck Transformer + **Focal-EIoU 损失**，专门优化「互相遮挡小目标」的掩膜 |
| 遮挡专用分割 | **OccPepSeg-YOLO** | boundary-aware 损失（BDoU）+ BoundaryGate + P2FreqFusion，直接针对边界 |
| 边缘细化模块 | **MSERM + SEAM**（YOLOv11 改进） | 多尺度边缘细化 + 分离增强注意力，改善粘连/遮挡处的掩膜边界 |
| 事件相机 | **ATR + TAM + DMR**（EV-SpSegNet 扩展） | 方向掩膜正则化 DMR，抑制训练时过量正调制 —— 思路可迁移到掩膜正则 |
| 航空场景分割 | **ISDNet** | HTC + 膨胀卷积扩大空间上下文 + mask 分支残差连接 |

> ECM 的架构改进（3.2）需要**重训模型**，成本较高；本报告把它列在最后一档。

## 四、后处理 / 工程手段（不重训、立刻可用）

### 4.1 检测稳定器：双阈值滞回 + 时间滤波（TemporalHysteresisStabilizer）

这是一个**通用且极便宜**的消抖模式，专门治「目标忽隐忽现」：
- **时间滤波**：检测需连续 `min_frames` 帧出现才被确认（滤掉 1~2 帧的瞬时虚检）
- **双阈值滞回**：
  - `appear_conf`（高，如 0.5）：新目标出现的严格门限
  - `persist_conf`（低，如 0.3）：**已确认目标**维持的低门限 → 「难出现但更难丢失」
- **间隙容忍**：允许最多 `max_gap` 帧无检测不移除轨迹（处理短暂遮挡/漏检）

> 对本项目：这与 `stitch_tracks` 是互补的 —— 滞回在**在线阶段**防止编号断裂，
> `stitch_tracks` 在**离线阶段**把已断的重新接上。可以两者都做。

### 4.2 前帧记忆叠加（航拍专用，来自实战）

针对**航拍视频识别框闪烁**的土办法，但原理扎实（YOLO 不记忆上一帧）：
在 NMS 前把上一帧的置信度图**衰减后叠加**到本帧对应位置：
```python
prediction[..., 4] += pre_predic * 0.5   # 权重 0.05~0.5，无人机场景建议偏低
```
> 「上一帧认为是车，下一帧就有更大概率仍然认为是车」→ 直接抑制忽隐忽现。

### 4.3 光流插值补掩膜（不重训、对俯视很实用）

盲道导航系统的做法（**策略与俯视遮挡高度同构**）：
- 每 N 帧才跑一次完整 YOLO 推理；**其余帧用 Lucas-Kanade 光流追踪特征点重建掩膜**
- 当 IoU 低于阈值时强制重新检测
- 实测「计算量降低约 75%，同时保持导航的连续性和稳定性」，
  并且原文明确指出：**「光流追踪能平滑掩膜的时序抖动，减少单帧检测不稳定导致的跳变」**

> 对本项目：视频帧率 30fps 且场景连续，光流补帧对"遮挡造成的 1~18 帧缺失"是天然解法。
> 本项目当前用「缺失帧插值」，可升级为「光流外推」，运动更真实。

## 六、一句话总结

> 俯视图的遮挡不是"目标不可见"，而是"目标被高空物切成碎片/瞬间切断"。
> **官方给的第一答案是换跟踪器**——`fasttrack.yaml` 是唯一以遮挡为中心的，
> 其 7 个 `*_occ` 参数直接调节遮挡行为；**第二答案是训练侧 `copy_paste`/`cutmix` 增强**；
> **最有价值的学术参考是形状感知卡尔曼**，它最重要的一句是：
> **匹配门限设得太严反而加剧身份碎片化，IoU 阈值 0.3 优于 0.5。**
> 对本项目而言，最省力的组合是：`fasttrack`（调 3 个 occ 参数）+ `with_reid: True(auto)` + 滞回稳定器，
> 三者叠加即可在**不重训**的前提下明显改善 9.mp4 的掩膜闪断与编号跳变。
