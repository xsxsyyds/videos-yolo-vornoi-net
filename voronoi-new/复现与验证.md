## 轮廓缓存格式

`frames64.pkl` 是 Python pickle 字典：

```python
{
    'meta': (width, height, fps, frame_count, effective_top, effective_bottom),
    'frames': [
        {
            'polys': np.ndarray((M, 64, 2), dtype=np.float32),
            'tid': np.ndarray((M,), dtype=int),
            'cls': np.ndarray((M,), dtype=int),
            'num': np.ndarray((M,), dtype=int),
        },
        # 每个视频帧一项，包括没有目标的空帧
    ],
}
```

`tid` 是轨迹 ID，`cls` 是类别 ID，`num` 是显示编号。各数组相同位置必须对应同一个对象；帧序号从 0 开始。空帧的 `polys` 应为 `(0,64,2)`。点按闭合轮廓顺序存储，不额外重复首点，所有坐标必须有限。

当前入口固定按 64 点验证输入。若以后接入其他点数，应明确修改输入约束和日志定义，不能通过简单补点声称提高了掩码几何精度。

## 从 pass1 重新建立轮廓

直接使用未经清理、平滑的 pass1 轮廓会与已标注视频不完全一致。本例先重建原离线处理过程：

| 步骤 | 参数 |
|---|---|
| 轨迹拼接 | max_gap=40，max_res=90，max_angle=60，距有效边界 60 像素 |
| 粘连掩码清理 | area_ratio=1.45，cover=0.5，look=3，max_len=12 |
| 重叠冲突清理 | jump=0.8，base_thr=0.25，drop_conf=0.6，center_ratio=0.35 |
| 短轨迹过滤 | 检测帧少于 5 帧则去掉 |
| 框平滑及间隙 | win=15，max_gap=45 |
| 轮廓平滑 | poly_win=11，poly_outlier=2.2 |
| 形状变化及收边 | shape_max=0.06，clamp_tol=0.03 |
| 掩码缺口插值 | poly_fill_gap=20，fill_max_body=2.5 |

脚本会断言清理后的轨迹 ID、类别、显示编号、首尾帧和原检测帧数量与 JSON 一致，再生成缓存。它针对本例固定参数；其他视频若使用不同参数，需同步调整后处理，不能只替换文件名。

```powershell
Set-Location 'E:\AAA-reseach\packet\voronoi-new'
$python = 'E:\AAA-reseach\env\yolo26\python.exe'

& $python prepare_tracks.py `
  --pass1 'E:\AAA-reseach\videos\new-track\_cache\14-10.20_pass1.pkl' `
  --tracks-json 'E:\AAA-reseach\videos\new-track\_cache\14-10.20_tracks.json' `
  --out-dir '.\outputs\prepared14'

# 使用新生成的缓存
$env:VORONOI_DEPS = 'E:\AAA-reseach\videos\new-track\voronoi-test\deps'
& $python render_video.py --config '.\configs\14-10.20.json' `
  --cache '.\outputs\prepared14\frames64.pkl' `
  --out-dir '.\outputs\reproduced14'
```

这里不运行检测模型，不需要 `best.pt`。`tracking_postprocess.py` 保存了原跟踪脚本以便追溯，但当前包只调用其中的离线函数；不将其作为新的模型推理入口使用。

## 验证覆盖

原全片验证包含：

1. 输入视频与缓存的帧数、宽高、帧率相符。
2. 顺序处理全部 2901 帧，每帧保留 64 点轮廓并写一条日志。
3. 每条已生成重叠折线在编码前的网络中没有缺失像素。
4. 编码完成后完整解码，确认输出帧数、尺寸和帧率。
5. 抽查 6 帧，验证布尔修复没有修改原始 64 点；47000 次点内外判定与奇偶规则一致；分区面积守恒且交点位于原轮廓上。

上述检查不等于完整的解析维诺图正确性证明。特别是“规定折线像素完整”只验证已成功规划的折线，不包含因歧义而跳过的对象对。

## 后续优化方向

优先处理三岔点失败和无法括根的边，建立可验证的局部自适应细分；其次定义三重重叠、包含和交点排序歧义的统一规则。优化速度时，应保持同一输入、网格和分界定义，再比较时间与输出差异。当前已有的 CPU 并行结果不能自动推导 GPU 或更多进程一定更快。
